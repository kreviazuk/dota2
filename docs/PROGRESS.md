## 常用命令
```bash
npm install
npm test            # Vitest 单元测试
npm run typecheck   # tsc --noEmit
npm run dev         # 浏览器开发服务器：主菜单 → 选难度 → 对局（手机横屏触屏或键鼠）
npm run sim -- --games 20 --seed 1 --difficulty normal   # 无画面 AI 对 AI 批量对战 + 平衡报告（每局约 10 秒）
npm run build       # 类型检查 + 生产构建到 dist/
```
工具链：TypeScript 7、Vite 8、Vitest 5、Node 24。

## 如何运行 / 试玩
- **电脑浏览器**：`npm install` 后 `npm run dev`，打开终端里显示的 `Local` 地址（默认 http://localhost:5173 ，端口被占用时 Vite 会换一个）。
- **手机**：`npm run dev` 已经带了 `--host`，终端里还会显示一个 `Network` 地址（电脑的局域网 IP）。手机连同一个 Wi-Fi，用浏览器打开这个地址，横屏游玩（竖屏会提示"请将手机横屏游玩"并自动暂停）。电脑防火墙需要放行这个端口。也可以 `npm run build && npm run preview` 用生产构建试玩（端口 4173，同样带 `--host`）。
- **流程**：主菜单（背景是 AI 演示对局）→ 选难度（简单 / 普通 / 困难）→"开始游戏（斧王）"→ 对局 → 胜负结算（再来一局 / 返回主菜单）。你控制天辉（下方）的 1 号斧王，两名队友和三名敌人由 AI 控制；先推倒对方遗迹获胜。
- **触屏操作**：左下摇杆移动；右下大按钮"攻击"（优先攻击附近的敌方英雄，其次小兵、建筑；按住持续攻击）；"补刀"打一下能打死的血量最低的小兵，"推塔"打最近的敌方建筑；"回城"5 秒后回到泉水（受到伤害会打断）；技能键轻点 = 智能施法（自动选目标），按住拖动 = 手动瞄准（显示范围和落点，拖到技能键上方出现的"取消"区可以取消）；技能键左上角的"+"= 加点（未学会的技能直接点按钮也能学）；右上角暂停。
- **键盘（网页调试用）**：方向键或 A / S / D 移动（W 留给技能），Q W E R 朝鼠标方向施法，Shift+Q/W/E/R 加点，空格 攻击，T 回城，Esc 暂停 / 继续。

## 批量模拟基线
P1 最终基线（Task 16，普通难度 10 局，种子 1–10）记录在 `docs/balance/balance-log.md`：推掉遗迹 4 局（天辉 1 / 夜魇 3，平均 33:45），超时 6 局（判定天辉 4 / 夜魇 2），13–22 分钟内结束 0%（目标 ≥ 80%）；3/6/10/14 分钟平均等级 5.6 / 10.6 / 16.6 / 21.8，净资产 1979 / 3938 / 6989 / 10351。对局偏长是 P3–P5 要解决的首要问题。

### Task 13 完成时的统计（3 斧王 vs 3 斧王，种子从 1 开始）
| 难度 | 局数 | 天辉胜 | 夜魇胜 | 超时（40 分钟，按建筑血量 + 净资产判定） | 已结束对局的平均时长 |
|---|---|---|---|---|---|
| 普通 | 20 | 45% | 20% | 7 局（判定天辉 5 / 夜魇 2） | 27:28（中位 26:28，17:41–39:49） |
| 简单 | 10 | 90% | 10% | 0 | 28:41 |
| 困难 | 10 | 20% | 30% | 5 局（判定天辉 2 / 夜魇 3） | 28:41 |

- 普通难度：13–22 分钟内结束的只有 15%（验收目标 ≥ 80%，属于 P5 调参）。平均等级 3:00 = 5.7、6:00 = 10.6、10:00 = 16.7、14:00 = 21.9（目标 6 / 10 / 15 / 19，中后期偏快，约 20 分钟满级）；平均净资产 2003 / 3934 / 7032 / 10462（没有物品，只是金钱）。一塔约 6.5–9 分钟、二塔约 14–16 分钟、三塔约 21 分钟被推。
- 阵营对称性：120 局镜像对局中先丢一塔的是天辉 56 次、夜魇 64 次，击杀 1074 : 1091，没有系统性偏差。上表普通难度 20 局里天辉略多属于样本噪声。

## 实施中做出的决定（偏离或补充计划的地方）
- 键盘操作：学技能用 Shift+QWER（Ctrl+W 会关闭浏览器标签页）；移动用方向键 + A/S/D（W 留给技能）。只影响网页调试。
- 减益免疫：只挡**敌方**的纯粹法术伤害（与 7.41 黑皇杖一致），自己和友方造成的伤害不受影响。
- `stop` 会打断所有施法；`move`/`moveTo` 不会打断允许移动的引导技能。
- `abilityCooldown(ab, caster?)` / `abilityManaCost(ab, caster?)`：天赋可以用 `技能id.cooldown` / `技能id.manaCost` 键加减冷却和耗蓝。
- 英雄在引导中死亡时，会以"被打断"触发 `onChannelEnd`。
- 回城期间受到伤害（包括发起回城的同一帧）会被打断。
- 攻城车按 `波次 % 4 === 0` 出现，而且需要游戏时间 ≥ 3:00，所以第一辆出现在 3:30。
- 超级兵只有生命和攻击的成长翻倍，赏金成长不翻倍。
- 英雄被塔或小兵击杀、且没有敌方英雄可以记功时，附近的敌方英雄仍然拿助攻金。
- `cloneBalance` 的深合并没有防御未知的嵌套键（参数有编译期类型检查；如果 P5 的模拟工具改为读 JSON 覆盖参数，需要加固）。
- 斧王·一人之军：按资料实现"友方英雄进入 350 范围后加成在 3 秒内线性消失"（计划里是立即消失）；友方离开后立即恢复。测试相应改为等 3 秒再检查。
- 斧王·狂战士之吼：斧王死亡后嘲讽立即结束（否则被嘲讽者剩余时间内无法操作）；被嘲讽单位的原有指令（包括回城、走向施法目标）被清空；不嘲讽隐藏单位。
- 斧王·反击螺旋：计数在斧王死亡和技能升级时清零；内置冷却 0.3 秒放在技能数值 `cooldown` 里。
- 反弹伤害（`reflected`）不触发技能吸血（改了 `damage.ts`，与 7.41 说明一致）。
- 淘汰之刃：永久护甲每层数值读 `abilityValue`（含天赋）；智能施法/AI 的搜索距离用 `abilityCastRange`（含施法距离加成）而不是写死 175。
- 测试里直接改技能等级后需要调用 `syncPassives`，被动 Modifier 才会挂上（正常加点走 `learnAbility` 会自动同步）。
- 普攻同帧结算（Task 13 发现的 sim 问题）：同一帧完成前摇的攻击先收集、再统一出手，双方互相致死时都能打中。原来按 `world.units` 的顺序依次结算，天辉兵总是先刷出、排在前面，两波完全相同的兵对撞时天辉赢 74%；修改后约 50%。
- 泉水射程从设计文档的 1100 改为 500：泉水离遗迹只有 400、离 T4 约 760，1100 会覆盖整个高地，泉水每秒 1000 伤害，遗迹基本打不掉（AI 对局 8 局全部超时）。500 仍覆盖复活点和回复区，但从正面进攻遗迹时打不到。
- 简单 AI 相对计划代码的修改：
  - 正在施法（前摇或引导）时不再重复下施法指令。计划代码每次思考都会重下，而重新施法会取消当前施法；困难 AI 的思考间隔（0.2–0.275 秒）比斧王的 0.3 秒施法前摇还短，永远放不出技能，导致困难夜魇 6 局全败。
  - 遗迹不会攻击，英雄可以直接打，不需要小兵在旁边抗塔（计划代码要求小兵在"射程 + 半径"内，遗迹射程是 0，所以英雄永远不会打遗迹）。
  - 新增推进模式：敌方英雄全灭，或我方存活英雄比敌方多 2 个以上，且自己血量 > 50% 时，直接攻击最近的可攻击敌方建筑，不再躲塔（泉水仍然会躲）。20 局对比：结束的对局从 9 局增加到 12 局。
- `npm run sim`：超时局按设计文档 §11.1 的安全阀判定胜负（每座存活建筑按剩余血量比例计 0–1 分，加上全队净资产占双方总和的比例 0–1 分），在终端里标红；另外检查参数，每局输出种子。
- 新增 `tests/ai.test.ts`：加点顺序、低血回城、困难 AI 能放完技能、无兵时打遗迹、敌方英雄存活时不硬抗塔、敌方全灭时推塔。
- 渲染（Task 14）相对计划代码的修改和补充：
  - 血条、等级数字和飘字按 `Camera.uiScale` 放大：视口高度低于 720 CSS 像素时放大 720 / 高度 倍（最多 2 倍）；英雄血条完整放大，小兵和建筑的血条只放大一半（否则一波兵的血条会叠成一片）。原因：屏幕高度对应 1400 世界单位，手机横屏（约 390 像素高）时计划里的尺寸只有 5–7 像素，看不清。`drawBars` 的第 7 个参数是选项对象 `{ killMarker, time, uiScale }`，`fx.drawTexts(ctx, uiScale)`。
  - 淘汰之刃斩杀标记（设计文档 §6.3）：镜头跟随的英雄学会淘汰之刃后，敌方英雄血条上画一条斩杀线刻度；血量 ≤ 斩杀线（含天赋加成）且可以被选中时，血条右侧显示斧头标记；技能暂时放不出（冷却、魔法不足、眩晕/沉默、已死亡，按 `canCast` 判断）时刻度和标记变暗。只对英雄显示（小兵的血量大多在斩杀线以下，显示出来会刷屏）。斩杀类技能在 `src/render/unitDraw.ts` 的 `EXECUTE_ABILITIES` 里登记，P2 的其他英雄可以复用。新增 `tests/renderLogic.test.ts` 测试这部分逻辑。
  - 泉水池和建筑废墟画在地面层（先于所有单位）。计划里泉水和单位一起按 y 排序，而出生点在泉水中心上方 150、泉水画成半径 170 的圆，会盖住刚出生的英雄。
  - 新增回城和引导技能的脚下进度圈（回城蓝色、引导金色）。计划和 Task 15 的 HUD 里都没有显示回城进度。
  - 处于 `hidden` 状态的敌方单位不绘制，己方的画成半透明（P1 还没有技能用到这个状态，先防止以后泄露位置）。
  - 塔的血条画在塔底往上 150 处（计划是 130，会压住基地塔顶部的水晶）。
  - 浏览器截图验证（Playwright + 预装 Chromium，1600×800 和 844×390@2x，临时测试页面没有提交）：地图、树林、河道、建筑、无敌护盾、小兵、英雄、弹道、各种特效和飘字、斩杀标记、回城圈都正常，控制台没有报错。headless 里 `render()` 的 CPU 耗时约 1.4 毫秒/帧（不含 GPU 光栅化）。设计文档 §10.4 要求"静态地图层预渲染到离屏 Canvas、粒子和飘字用对象池"，这里按计划只缓存了地面噪声图块和树木精灵；Task 16 真机测试帧率不够时再做。
- 操作和界面（Task 15）相对计划代码的修改和补充：
  - 界面尺寸单位：计划全部用 `vh`，手机横屏（约 390 像素高）时 1vh 只有 3.9 像素，按钮文字只有 6–8 像素。改为 `html { font-size: clamp(4.5px, 1vh, 9px) }`，所有尺寸用 `rem`（≈1% 屏高，手机上略放大、大屏不超过 9 像素），文字再加 `max(…, Npx)` 的最小字号。补刀/推塔/回城按钮从 8 放大到 9 单位，暂停按钮从 6 放大到 7。
  - 技能键按圆弧重新排布（以普攻键中心为圆心、半径 20rem、间隔 36°），补刀/推塔列左移，避免相邻按钮贴在一起。加点"+"放在技能键左上角（圆弧外侧）：计划放在右上角，截图里会压住相邻的技能键。冷却中隐藏技能名（否则和冷却数字叠在一起）；魔法不足、未学会只让按钮本身变暗，"+"保持醒目；触屏设备上隐藏 Q/W/E/R 键位字母。
  - 拖动瞄准的方向和距离从手指按下的位置算起（计划从按钮中心算：按在按钮边缘时手指稍微一抖就会变成手动瞄准）。拖满施法距离所需的距离改为屏高的 20%（60–130 像素，计划固定 120 像素，手机上往下拖不到）。
  - 瞄准计算抽成纯函数 `src/input/aim.ts`（`aimAbility`、`pointCastTarget`），用真实的 World 测试；技能半径读 `abilityValue`（含天赋，例如斧王 25 级天赋的吼范围）。
  - 普攻键按下时立即下一次智能攻击（计划只在按住期间由 `drain()` 下指令，按下和松开落在同一个逻辑帧之间的快速轻点会丢失），按住期间每 0.5 秒重新选目标。
  - 未学会的技能可以直接点按钮本身加点（"+"只有 5.5rem，手机上不好点）；已学会的技能仍然只能点"+"加点，避免误施法。
  - HUD 根节点改为不接收触摸（计划的 `#ui > *` 规则让整个 HUD 盖住画布），只有摇杆区和按钮接收；鼠标位置在 window 上跟踪（键盘 QWER 朝鼠标施法）。窗口失焦时清空按键，避免英雄一直走。
  - 暂停和继续时调用 `Controls.reset()`：丢弃暂停期间积累的指令和按住中的输入，并发一次"停止摇杆移动"。Esc 可以暂停也可以继续；转成竖屏（被"请横屏"提示挡住）和切到后台时自动暂停；对局结束后不能再暂停。
  - 主循环：计划里演示局结束会再次调用 `startDemo()`，在主菜单上叠第二个开始界面；改为只换一局新的演示对局。结算前等待 1.8 秒期间的定时器在退出/重开时会被清掉。对局结束后渲染插值系数固定为 1。

## 已知的小问题（推迟处理，不影响功能）
主要是测试覆盖不足，例如嘲讽/引导期间不能移动、塔的强制目标 3 秒后失效、队伍金钱倍率等没有测试；另有少量写死的常量（小兵攻速 100、伤害 ±2 浮动、出兵阵型偏移）尚未移入 `BALANCE`。
斧王 10 级天赋 A（每个生效中的战斗饥渴 +8% 移速）只有数据，按计划在 P2 实现。淘汰之刃直接斩杀时不经过 `applyDamage`，所以不会更新目标的 `lastHeroDamage`（斧王本身就是击杀者，不影响记功）。

性能：只在 headless Chromium（无 GPU）里测过，还需要在真机（中端安卓，目标 60fps）上确认。镜头一次移动很远时（开局、复活、回城、镜头跟随切换）会在一帧里生成一行或多行新图块，4 倍 CPU 降速下这一帧最多约 28 毫秒；如果真机上能感觉到卡顿，可以在复活/回城前按目标位置预热图块。剩下最大的逐帧开销是飘字的 `strokeText`（每帧约 0.2 毫秒）和血条。

AI：1 级时双方血量相当，`pickHeroTarget` 总是出手换血，三个斧王常常同时开吼，第一波兵交汇（约 0:25）时会打成 3v3 团战，几个英雄几秒内掉到 30% 以下、0:40 左右回城到泉水，损失前几波兵的经验和金钱（双方对称，不是 bug）。P4 的对线 AI 应该在前几级以补刀为主，换血按决策掷骰，并避免多人同时交同一个控制技能。`moveTo` 到达目的地后指令仍然是 `moveTo`，英雄会站着不自动攻击（只影响 AI，玩家操作不用 `moveTo`；AI 会显式下攻击指令，影响不大）。计划里 `pickHeroTarget` 的 `focus` 在每次思考时都掷骰（每秒约 4 次），实际效果是"经常在劣势时也上去打"；P4 重写 AI 时应该改成按决策掷骰。
