## 常用命令
```bash
npm install
npm test            # Vitest 单元测试
npm run typecheck   # tsc --noEmit
npm run dev         # 浏览器开发服务器：主菜单 → 选难度 → 对局（手机横屏触屏或键鼠）
npm run sim -- --games 20 --seed 1 --difficulty normal   # 无画面 AI 对 AI 批量对战 + 平衡报告（每局约 10 秒）
npm run build       # 类型检查 + 生产构建到 dist/
```
工具链：TypeScript 7、Vite 8、Vitest 5、Node 24。

## 如何运行 / 试玩
- **电脑浏览器**：`npm install` 后 `npm run dev`，打开终端里显示的 `Local` 地址（默认 http://localhost:5173 ，端口被占用时 Vite 会换一个）。
- **手机**：`npm run dev` 已经带了 `--host`，终端里还会显示一个 `Network` 地址（电脑的局域网 IP）。手机连同一个 Wi-Fi，用浏览器打开这个地址，横屏游玩（竖屏会提示"请将手机横屏游玩"并自动暂停）。电脑防火墙需要放行这个端口。也可以 `npm run build && npm run preview` 用生产构建试玩（端口 4173，同样带 `--host`）。
- **流程**：主菜单（背景是 AI 演示对局）→ 选难度（简单 / 普通 / 困难）→"开始游戏（斧王）"→ 对局 → 胜负结算（再来一局 / 返回主菜单）。你控制天辉（下方）的 1 号斧王，两名队友和三名敌人由 AI 控制；先推倒对方遗迹获胜。
- **触屏操作**：左下摇杆移动；右下大按钮"攻击"（优先攻击附近的敌方英雄，其次小兵、建筑；按住持续攻击）；"补刀"打一下能打死的血量最低的小兵，"推塔"打最近的敌方建筑；"回城"5 秒后回到泉水（受到伤害会打断）；技能键轻点 = 智能施法（自动选目标），按住拖动 = 手动瞄准（显示范围和落点，拖到技能键上方出现的"取消"区可以取消）；技能键左上角的"+"= 加点（未学会的技能直接点按钮也能学）；右上角暂停。
- **键盘（网页调试用）**：方向键或 A / S / D 移动（W 留给技能），Q W E R 朝鼠标方向施法，Shift+Q/W/E/R 加点，空格 攻击，T 回城，Esc 暂停 / 继续。

## 3D 渲染器（Three.js，2026-10-08）
用户反馈 2D 俯视画面"太平"、人物"太单薄"（一个圆加一把武器），要求改成真正的 3D。现在默认用 Three.js（r186）渲染，画面是倾斜镜头下的低多边形 3D MOBA；美术仍然全部由代码生成（基本体拼模型、Canvas 画纹理），没有任何外部素材。sim / ai / game 没有改动，渲染层仍然只读 World、只消费事件队列。

### 结构（`src/render3d/`）
- `coords.ts`：唯一的坐标换算处。sim (x, y) → Three (x, 高度, y)，1 世界单位 = 1 Three 单位；`facingToRotY` 把 sim 朝向换成模型旋转（所有模型面朝本地 +Z）；`groundHeight` 给出地形高度（道路和基地是平的 0，河床下凹 26，树林地面高 16）。
- `camera3d.ts`：`Camera3D`，透视镜头，俯角 54°、垂直视场角 36°，距离按"屏幕正中一列覆盖 1400 世界单位地面"算出（与 2D 镜头的屏高一致）；从南边朝北看，屏幕上方 = 夜魇；镜头中心比英雄往敌方偏 230，x 方向最多偏离中线 320。屏幕 ↔ 世界通过镜头射线与地面求交（`screenToWorld` / `worldToScreen` / `footprint`）。
- `src/render/view.ts`：`ViewCamera` 和 `GameRenderer` 接口。2D 的 `Camera` / `Renderer` 和 3D 的 `Camera3D` / `Renderer3D` 都实现它们，操作层（拖动瞄准、鼠标施法）、HUD（小地图视野框，3D 时是梯形）和主循环只依赖接口。
- `mapScene.ts`：启动时搭一次的静态地图。非均匀地形网格（只在道路边缘和河岸细分）；1024×3072 的程序地面纹理（树林地面、土路和车辙、基地石板、遗迹广场纹样、夜魇熔岩裂缝、河岸沙地，树的影子直接画进纹理）乘一张平铺的细节噪声；动画水面着色器（波纹、高光、岸边泡沫）；约 5000 棵实例化的树（3 种造型 × 天辉/夜魇两套配色，随风摆动），石头、草丛按"左树林 / 道路 / 右树林 × 每 1500 一行"分格实例化，镜头外的格子整组剔除；基地装饰（天辉白石柱 + 绿火盆，夜魇黑尖石 + 熔岩晶体）。
- `models/axe.ts`：斧王，13 根骨骼（身体、骨盆、躯干、头、双臂两节、双腿两节、斧子），部件按绑定姿势合并成一个刚性蒙皮网格，一个英雄只需 1 次绘制（+1 次阴影）。姿势函数：站立（呼吸）、跑（步频按实际移速）、普攻（前摇 0–60% 举斧、60–100% 劈下，命中瞬间正好是 sim 出手的时刻，之后收招）、狂战士之吼（蓄力 → 张臂怒吼）、战斗饥渴（左手指向目标）、淘汰之刃（双手举过头顶 → 跳劈）、反击螺旋（双臂平伸旋转一圈）、回城（半蹲拄斧）、眩晕、被嘲讽时摇晃、死亡（向后倒地后沉入地面）、复活（弹出 + 光柱）。状态切换时 0.14 秒姿势混合；朝向平滑转身。模型比小兵大很多（缩放 1.3，头顶约 230）。
- `models/creeps.ts`：近战兵（剑盾步兵）、远程兵（兜帽法师 + 发光法球）、攻城车（投石车，车轮随移动转动，投石臂随前摇后拉、出手甩出），超级兵放大 1.2 倍并加金边；两边阵营造型不同（天辉银甲绿披风圆盾，夜魇黑甲尖盔六角盾）。小兵不在场景里挂网格：每个小兵只有一棵不入场景的骨骼树，摆好姿势后把各部件的世界矩阵写进按"类型 + 阵营 + 部件"共享的 InstancedMesh，一屏小兵只要十几次绘制；死亡时侧身倒下沉入地面（sim 里小兵死亡即移除，渲染层保留外观播完 1.5 秒死亡动画）。
- `models/buildings.ts`：防御塔（八边形塔基、扶壁、塔身、阵营色旗帜和箍、垛口、托爪 + 旋转浮动的发光水晶和光晕；夜魇版黑石加尖刺）、遗迹（三层塔基 + 石柱 / 尖刺王冠 + 大水晶）、泉水（贴地的池沿 + 发光池面 + 中央石柱）、废墟（碎石堆和熄灭的水晶碎片）、无敌护盾（菲涅尔边缘发光的穹顶）。建筑挡住身后（北边）的英雄时淡成半透明；血量低于一半时冒烟。
- `decals.ts`：贴地圆环着色器（实线 / 虚线 / 进度弧 / 填充 / 柔边），用于阵营圈、瞄准范围圈、技能落点、引导和回城进度圈、区域效果、冲击环。
- `fx3d.ts`：3D 特效（两组 Points 粒子、冲击环、光柱、斩击弧、全屏闪光）和飘字。事件到特效的对应和 2D 版一致：受击火花、死亡血雾和尘土、建筑爆炸（火花 + 碎石 + 尘环 + 光柱 + 震屏）、升级金环 + 光柱、复活蓝光柱、回城、狂战士之吼冲击波、反击螺旋旋风斩、战斗饥渴爆发、淘汰之刃斩击（斩杀时双斩击、红光柱、"淘汰！"和全屏红闪）。弹道是带高度弧线和拖尾粒子的发光球（攻城车是带尘土拖尾的石块，抛物线最高约 260）。头顶状态：战斗饥渴（胸口环绕的红色碎片 + 脚下脉动红圈）、嘲讽（红色"!"）、眩晕（金星）。
- `anim.ts`：纯逻辑的动画状态机 `AnimTracker`（状态优先级、前摇进度、收招判定、步态相位、一次性动作、死亡计时、受击闪光）。
- `renderer3d.ts`：`Renderer3D` 总控。光照：半球光 + 一盏平行光（阴影贴图手机 1536、桌面 2048，阴影相机的范围按镜头可见地面四边形在光源坐标系里的外接矩形算一次，每帧只平移并对齐到阴影像素，镜头移动时影子不闪）；卡通明暗（4 阶）+ 轻微边缘光，受击时闪红。
- 界面层：WebGL 画布上方一层透明 2D 画布，在投影后的头顶位置复用 2D 的 `drawBars`（血条、蓝条、等级、斩杀线和斧头标记）和 `drawFloatText`（飘字），尺寸和 2D 版完全一致。`drawBars` 新增可选的 `top` 参数。

### 后备和接入
- `src/render/createRenderer.ts`：WebGL 2 可用时动态加载 3D 渲染器（three 是单独的代码块）；不可用、初始化失败，或网址带 `?renderer=2d` 时用原来的 2D 渲染器（保留未删，换一块新画布）。`main.ts` 启动时异步选择渲染器，开始界面的演示局、对局、暂停、结算都走同一个接口。
- 设备像素比：3D 画布触屏设备上限 1.5、桌面 2（桌面开 MSAA），界面层上限 2。
- 开发钩子 `window.__game` 新增 `timeScale`（慢放，自动化截图用）；`Camera3D` 有调试用的 `zoom` / `debugView`（自由镜头），正式游戏不会改它们。

### 性能（headless Chromium + SwiftShader 软件 GPU）
- 场景：Task 16 同款 3v3 团战（8:00，最多 35 个单位），915×412@2.625 触屏视口，测 5 秒。
- SwiftShader 在 CPU 上做顶点处理和光栅化，只能跑 2–6 fps，而且会通过命令队列反压拖慢 JS，所以直接测的帧时间没有参考价值。为了测 CPU 端开销，另跑一遍把 WebGL 的 draw 调用替换成空函数（其余 WebGL 调用、上传、Three.js 的全部工作照常）：每帧脚本时间（rAF 回调，含逻辑帧 + HUD + 渲染）平均 2.8 毫秒、p95 5.6，60 fps；CPU 4 倍降速时平均 7.3、p95 13.2，60 fps（2D 版同条件是 1.3 / 2.7 和 7.0 / 13.7）。其中 `gl.render`（Three.js 遍历、剔除、提交绘制）约占 70%。
- 绘制调用每帧约 80–140 次（含阴影），三角形约 16–20 万。优化过程：树改成实例化分格 + 影子画进纹理（三角形从约 92 万降到 19 万）、英雄合并成蒙皮网格（绘制调用从 220 降到 110 左右）、石头分格、地形网格只在坡上细分。
- 包体：原来 99 kB（gzip 34 kB）；现在主包 79 kB（gzip 28 kB）+ 3D 渲染器代码块 666 kB（gzip 175 kB，基本是 three）+ 2D 后备 23 kB（按需加载）。

- 渲染（2026-10-08，用户要求）：画面从 2D 俯视 Canvas 改成 Three.js 3D（倾斜透视镜头、光照和阴影、带动画的低多边形模型），美术仍然全部由代码生成。原 2D 渲染器保留为 WebGL 2 不可用时的后备（也可以用 `?renderer=2d` 强制）。设计文档 §2 / §10.4 里"2D 俯视、Canvas 2D"的描述以此为准。
- 3D 渲染的取舍：屏幕高度覆盖的地面长度和 2D 一样（1400），但透视下横向视野比 2D 窄（手机横屏约 2300–3300 而不是 3000），道路（1000 宽）始终完整可见；血条和飘字画在 2D 界面层上，所以和 2D 版一样大；树的影子是画进地面纹理的静态影子，单位走到树旁不会被树影遮住；防御塔比 2D 的"伪 3D"高，挡住身后英雄时自动变半透明；摇杆和拖动瞄准的方向仍按"屏幕方向 = 世界方向"处理（镜头没有偏航，只有俯仰，方向一致）。
- 键盘操作：学技能用 Shift+QWER（Ctrl+W 会关闭浏览器标签页）；移动用方向键 + A/S/D（W 留给技能）。只影响网页调试。
- 减益免疫：只挡**敌方**的纯粹法术伤害（与 7.41 黑皇杖一致），自己和友方造成的伤害不受影响。
- `stop` 会打断所有施法；`move`/`moveTo` 不会打断允许移动的引导技能。
- `abilityCooldown(ab, caster?)` / `abilityManaCost(ab, caster?)`：天赋可以用 `技能id.cooldown` / `技能id.manaCost` 键加减冷却和耗蓝。

  - 简单 AI 每次思考把所有已解锁、未选的天赋层一次选完（计划写的是只选 `pendingTalentTier` 返回的最低一层；AI 思考间隔约 0.2–0.4 秒，一次升很多级时逐层选会拖好几次思考）。
  - 天赋的加值和乘数对所有键统一按"基础 × 乘数 + 加值"计算（技能数值、`cooldown`、`manaCost`、`castRange`、`channelTime`、`charges`）；施法距离再加上属性里的施法距离加成。充能上限四舍五入取整。
  - 天赋让已经是充能制的技能多出充能时，多出的层数立即补上；原来不是充能制的技能变成充能制时直接给满层并清零冷却（计划要求）。
  - `pointSnap` 技能：落点总是相对施法者吸附，所以 `inCastRange` 对它恒为真（原地施放，不会走向落点）；只给方向时沿该方向吸附（没有施法距离的技能也一样）；`smartTarget` 返回的落点同样经过施法距离限制 / 吸附。拖动瞄准按最远一档换算拖动距离再吸附，指示器圈半径读 `values.radius`（或 `aimShape`）。
  - `smartTarget`：单位技能只要没指定 `unitId` 就调用（P1 行为不变）；其他类型只在指令里没有 `unitId` / `point` / `dir` 时调用。
  - `defaultToggled` 只对 `targetType: 'toggle'` 的技能生效。施法速度下限 −0.9（防止除零）。
  - 斧王 10 级天赋 A 统计所有身上带有斧王施放的战斗饥渴的存活单位（英雄和小兵都算，"每个生效中的战斗饥渴"）。
  - 自定义天赋 Modifier 必须 `persistOnDeath: true`：死亡时选的天赋如果用了不保留的 Modifier，`addModifier` 会拒绝，效果就丢了（代码不做强制，写天赋时注意）。
  - 计划要求 PROGRESS 和代码一起提交；实际按任务分派的要求单独提交 `docs: progress (P2 task 1)`。

## 已知的小问题（推迟处理，不影响功能）
主要是测试覆盖不足，例如嘲讽/引导期间不能移动、塔的强制目标 3 秒后失效、队伍金钱倍率等没有测试；另有少量写死的常量（小兵攻速 100、伤害 ±2 浮动、出兵阵型偏移）尚未移入 `BALANCE`。
斧王 10 级天赋 A 已在 P2 Task 1 实现。玩家英雄的天赋要等 Task 7 的天赋弹窗才能选（AI 英雄已经会选）。淘汰之刃直接斩杀时不经过 `applyDamage`，所以不会更新目标的 `lastHeroDamage`（斧王本身就是击杀者，不影响记功）。

性能：只在 headless Chromium（无 GPU）里测过，还需要在真机（中端安卓，目标 60fps）上确认。镜头一次移动很远时（开局、复活、回城、镜头跟随切换）会在一帧里生成一行或多行新图块，4 倍 CPU 降速下这一帧最多约 28 毫秒；如果真机上能感觉到卡顿，可以在复活/回城前按目标位置预热图块。剩下最大的逐帧开销是飘字的 `strokeText`（每帧约 0.2 毫秒）和血条。

AI：1 级时双方血量相当，`pickHeroTarget` 总是出手换血，三个斧王常常同时开吼，第一波兵交汇（约 0:25）时会打成 3v3 团战，几个英雄几秒内掉到 30% 以下、0:40 左右回城到泉水，损失前几波兵的经验和金钱（双方对称，不是 bug）。P4 的对线 AI 应该在前几级以补刀为主，换血按决策掷骰，并避免多人同时交同一个控制技能。`moveTo` 到达目的地后指令仍然是 `moveTo`，英雄会站着不自动攻击（只影响 AI，玩家操作不用 `moveTo`；AI 会显式下攻击指令，影响不大）。计划里 `pickHeroTarget` 的 `focus` 在每次思考时都掷骰（每秒约 4 次），实际效果是"经常在劣势时也上去打"；P4 重写 AI 时应该改成按决策掷骰。

3D 渲染器：只在 SwiftShader 软件 GPU 上测过，真机 GPU 帧率未测（CPU 端开销见上）；手机上首次出现新材质（第一波兵、第一个弹道、第一次技能特效）时会编译着色器，可能卡一帧（开始界面的演示局会提前编译大部分）；P1 没有眩晕技能，眩晕动作和金星标记只在代码里，没有在对局里见到；只有斧王一个英雄模型，P2 的其他英雄需要各自的模型和姿势函数（`HeroView` 目前直接用 `AxeModel`）；WebGL 上下文丢失只做了 `preventDefault`，依赖 Three.js 自动恢复，没有专门测试。
