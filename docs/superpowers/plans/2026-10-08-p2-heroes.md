# P2 英雄 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 玩家开局可以在 10 名英雄里选 1 名（电脑补齐其余 5 名）；10 名英雄的全部技能、先天技能和天赋都按 7.41f 数据实现，每个技能都有测试、能在游戏里正常释放；HUD 有天赋二选一弹窗和完整的加点界面（含 X1 额外技能键、充能和层数角标、自动加点开关）；简单 AI 会合理地使用每个英雄的技能，混合阵容的 AI 对局能正常打完；每个英雄都有自己的 3D 低多边形蒙皮模型和技能动作 / 特效，以及 2D 后备外观；`npm run sim` 支持随机混合阵容并输出各英雄的出场胜率。

**Architecture:** 不改变 P1 的分层。`src/sim` 先补齐这些英雄需要的通用机制（天赋、控制状态、强制位移、计时器、隐身规则、攻击信息扩展、分裂、伪随机、护盾、光环、召唤物……），再一个英雄一个文件地实现技能；英雄技能只用通用机制，不在系统代码里写某个英雄的特例。AI 的技能使用规则从 `AbilityDef.aiCast` 挪到 `src/ai/usage/<英雄>.ts` 的规则表。3D 渲染层增加"英雄模型注册表 + 共用人形骨骼 + 特效 / 弹道 / 状态外观注册表"，每个英雄只新增自己的模型文件和特效文件。选人分配（`src/game/draft.ts`）是纯函数，浏览器和批量模拟共用。

**Tech Stack:** TypeScript 7（strict）、Vite 8、Vitest 5、tsx、Three.js r186（3D 渲染）、Canvas 2D（后备渲染）、原生 DOM（界面）、Capacitor 8（安卓打包，GitHub Actions 构建）。

**Spec:** `docs/superpowers/specs/2026-09-29-dota-lane-design.md`（§6 英雄与技能、§9.3 选人、§10.1 场景流程、§10.2 HUD、§11.1 模拟工具、§14 P2）。数值：`docs/research/dota2-heroes.md`（其余 9 名英雄）、`docs/research/dota2-reference.md` §1（斧王）。已有的决定和偏离：`docs/PROGRESS.md`。P1 计划（格式参考）：`docs/superpowers/plans/2026-09-29-p1-core.md`。

**起点：** 分支 `claude/kind-ritchie-jz5131`，P1 完成 + 3D 渲染器，187 个测试全部通过。只有斧王（`axe`），天赋只有数据（`pickTalent` 指令没有实现，`TalentDef.stats` 没有生效），HUD 只有 Q/W/E/R 四个技能键，`HeroView` 直接用 `AxeModel`，`main.ts` 写死 3 斧王对 3 斧王。

## Global Constraints

- `src/sim/**`、`src/ai/**`、`src/game/**` 禁止使用 `document`、`window`、`HTMLElement`、`requestAnimationFrame`、`localStorage`、`performance`，禁止 `Math.random()`（`tests/purity.test.ts` 强制检查）。所有模拟随机数都来自 `world.rng`；`src/game/draft.ts` 这类纯函数接收一个 `Rng` 参数。渲染层（`src/render*`、`src/ui`）可以用 `Math.random()` 做纯视觉的随机。
- 逻辑步长：`TICK_RATE = 30`，`DT = 1/30`。坐标：世界单位 = Dota 单位，x 向右、y 向下，地图 3000 × 10000，天辉在下方。
- **数值来源：** 英雄技能数值一律以 `docs/research/dota2-heroes.md` / `dota2-reference.md` 为准，写在各英雄 `AbilityDef.values` 里；设计文档 §6.3 写明了调整的以设计文档为准（例如卓尔射手天赋失效距离 150、影魔三个毁灭阴影合成一个键）。资料没有给出、需要自己定的数字，用本计划"Decisions"一节的值；实现中又遇到新的，记到 `docs/PROGRESS.md` 的"实施中做出的决定"里。
- **可调参数：** 与具体英雄无关的通用参数（天赋解锁等级、光环残留时间、AI 阈值等）放进 `src/sim/data/balance.ts` 的 `BALANCE`，系统代码通过 `world.balance` 读取，不要写死。
- 界面文字全部用中文；代码标识符、文件名、技能 id 用英文。英雄 id：`axe`、`sven`、`pudge`、`juggernaut`、`phantom_assassin`、`drow_ranger`、`shadow_fiend`、`lina`、`zeus`、`crystal_maiden`。技能 id 用 `<前缀>_<技能>`，前缀分别是 `axe`、`sven`、`pudge`、`jugg`、`pa`、`drow`、`sf`、`lina`、`zeus`、`cm`。
- **每个任务结束时** `npm test`、`npm run typecheck`、`npm run build` 都必须通过；渲染或界面有改动的任务还要做 Playwright 截图检查（见下面的配方），并且**亲自打开截图看一遍**（Read 工具可以直接看 PNG）。游戏在每个任务结束时都必须能玩：`npm run dev` → 主菜单 → 开局 → 对局正常。

```bash

npm run dev -- --port 5173 --strictPort
```

`$SCRATCH/shot.cjs` 的骨架：
```js
const { chromium } = require('/opt/node22/lib/node_modules/playwright');
const OUT = process.env.SCRATCH;
(async () => {
  const browser = await chromium.launch({
    executablePath: '/opt/pw-browsers/chromium-1194/chrome-linux/chrome',
    args: ['--use-gl=angle', '--use-angle=swiftshader', '--enable-unsafe-swiftshader', '--ignore-gpu-blocklist'],
  });
  // 手机横屏（触屏）；桌面检查另开 { viewport: { width: 1280, height: 720 } }
  const page = await browser.newPage({ viewport: { width: 844, height: 390 }, deviceScaleFactor: 2, hasTouch: true, isMobile: true });
  const errors = [];
  page.on('console', (m) => { if (m.type() === 'error') errors.push(m.text()); });
  page.on('pageerror', (e) => errors.push(String(e)));
  await page.goto('http://localhost:5173/');
  await page.waitForFunction(() => window.__game && window.__game.session, null, { timeout: 60000 });
  // …按任务要求操作：点按钮、或用 page.evaluate 调用 window.__game 的开发钩子…
  await page.screenshot({ path: `${OUT}/example.png` });
  console.log(JSON.stringify({ errors }));
  await browser.close();
})();
```
运行：`SCRATCH=$SCRATCH node $SCRATCH/shot.cjs`。验收：控制台 0 报错，截图内容符合任务描述。

|---|---|---|
| D1 | 阿哈利姆神杖 / 魔晶 | **推迟到 P3**：P2 没有物品，玩家拿不到神杖和魔晶，提前实现无法验证。P2 不加 `hasScepter` 之类的开关；P3 物品任务里统一实现 10 名英雄的神杖 / 魔晶效果（设计文档 §6.4），新增的技能放 X2（幻刺的魅影无形已经占了 X1）。 |
| D2 | 选人界面 | 从 P4 提前到 P2（用户要求）。设计文档 §14 的 P4"选人流程"因此在 P2 完成；P4 只剩三层 AI、精英怪、结算界面细化。 |
| D3 | 天赋层编号 | `pickTalent` 指令沿用代码里的 `tier: 0 \| 1 \| 2 \| 3`（对应 10/15/20/25 级），不用设计文档 §2.4 写的 `10 \| 15 \| 20 \| 25`。解锁等级放 `BALANCE.hero.talentLevels = [10, 15, 20, 25]`。等级上限 25，所以 7.40 的"27–30 级自动补齐另一侧"不实现。天赋不消耗技能点。 |
| D4 | 天赋里的"+x%" | 技能数值本身是百分比的（分裂 60–90%、暴击 140–200%、神之力量 +110–190%、数箭齐发 80–140%、慢热 64%），天赋按**百分点相加**（+25% 分裂 = 60% → 85%）。"−x% 冷却 / 魔耗"按**乘法**（×0.75、×0.8）。帕吉 25 级"肢解 ×1.5（力量系数 ×1.8）""腐肉堆积与肉盾 ×1.5"按乘法。 |
| D5 | AI 技能规则放哪 | 从 `AbilityDef.aiCast` 挪到 `src/ai/usage/<英雄>.ts` 的规则表（用户要求"src/ai 里按英雄的技能使用表"），斧王的三条规则一起迁移，`aiCast` 字段删除。 |
| D6 | 隐藏（`hidden`）的含义（幻刺魅影无形） | 对敌方：不能被普攻、不能被技能选为目标、AI 和小兵 / 防御塔都不会锁定它，模型不绘制；范围技能和直线弹道照常命中（它在那里，只是看不见）。对友方：半透明。幻刺的模糊状态只有在 500 范围内没有敌方英雄和敌方防御塔时才是 `hidden`（设计文档 §6.3）。普攻会结束魅影无形，扔短匕不会。 |
| D7 | 视野类效果 | 本游戏没有战争迷雾：宙斯雷击 / 雷神之怒的视野、狂风"显形隐身单位"、肉钩命中后的视野全部忽略。雷神之怒按 7.41 规则也命中 `hidden` 的英雄（不命中无敌的）。 |
| D8 | 树木和地形 | 没有可破坏的树；肉钩、狂风等"穿过树木 / 悬崖"的描述自动满足。所有位移结束时用 `clampToWalkable` 限制在可行走区域内。 |

| D11 | 分裂伤害 | 斯温巨力挥舞：伤害 = 主目标这次攻击的"护甲减免前"伤害（含暴击和攻击类型系数）× 分裂比例，对梯形范围内其他敌人造成**无视护甲**的物理伤害；不打建筑，不触发吸血和攻击特效，不受技能增强。 |

**行为要点：**
- `abilityValue` 的计算顺序：`(levelValue(values[key]) + levelValue(values[key+'PerLevel']) × 英雄等级) × mult + add`。非英雄单位英雄等级按 1。先天技能（`slot === 'innate'` 或 `innate: true`）固定 1 级，靠 `PerLevel` 成长（7.41 规则：1 级就已经加上一次增量）。
- `newAbilityInstance`：`innate: true` 的技能 level = 1；`chargeTimers = []`。`canLearn` 对 `innate: true` 返回 false；`convertAttributePoints` 的"主技能学满"判断仍然只看 Q/W/E/R。
- 充能：`isReady` / `executeCast` / `tickCooldown` 改用 `abilityMaxCharges(caster, ab)`。`parallel`：施放时 `charges--` 并 `chargeTimers.push(abilityCooldown)`，每个计时器独立倒数，到 0 时 `charges++`。`sequential` 保持 P1 行为。天赋让一个原来不是充能制的技能变成充能制（宙斯 25 级"神圣一跳 3 层充能"）时，`pickTalent` 把 `ab.charges` 设为满、`cooldown` 清零。
- `instant`：`issueCast` 检查 `canCast` 后直接扣蓝、进冷却 / 充能、发 `cast` 事件、调用 `onCast({})` 和施法者的 `onAbilityCast` 钩子；**不**修改 `caster.cast`、`caster.order`、`attack.windup`。
- `smartTarget` 对所有目标类型生效：没有给目标时，`resolveTarget` 先调用 `def.smartTarget`（有的话），返回非 null 就用它。
- `targetType 'none'` 的技能：`resolveTarget` 透传 `given.dir`（返回 `{ dir }`，否则 `{}`），供神圣一跳这类"朝摇杆方向"的技能使用。
- `pointSnap`：`resolveTarget` 的 `point` 分支在算出落点后，把"施法者 → 落点"的距离吸附到 `pointSnap` 里最近的一档（方向不变，距离为 0 时用面向方向）。`aimAbility`（`src/input/aim.ts`）拖动时同样吸附，指示器圈的半径用 `values.radius`。
- `defaultToggled`：`learnAbility` 把等级从 0 升到 1 时，如果 `defaultToggled` 则设 `toggled = true` 并调用 `onToggle(ctx, true)`。
- 施法前摇：`updateAbilities` 用 `abilityCastPoint`；`src/render3d/anim.ts` 的 `animInput` 计算前摇进度也用它（否则影魔 25 级天赋时动画对不上）。
- 天赋：`pickTalent` 要求英雄等级 ≥ `talentLevels[tier]` 且该层未选；设置 `hero.talents[tier] = side`；把 `valueBonus` 的 `add` 累加进 `talentValueBonus`、`mult` 累乘进 `talentValueMult`；有 `stats` 时挂一个隐藏、不可驱散、`persistOnDeath` 的 Modifier（id `talent:<talentId>`，`stats` = 天赋的 stats）；有 `modifier` 时 `addModifier(world, u, def, { sourceId: u.id })`；然后 `syncPassives` + `recomputeStats`，发 `talent` 事件。`pickTalent` 指令（`applyCommand`）调用它，死亡时也可以选。
- 斧王 10 级天赋 A（每个生效中的战斗饥渴 +8% 移速）：`axe_t10a` 用 `modifier`：`stats` 函数统计 `world.units` 里带 `axe_battle_hunger`、`sourceId === 斧王` 的存活单位数 n，返回 `{ moveSpeedPct: 0.08 × n }`。其余 7 个斧王天赋的数据不变，现在通过 `pickTalent` 真正生效（`axe_t20b` 的 +15 力量走 `stats`）。
