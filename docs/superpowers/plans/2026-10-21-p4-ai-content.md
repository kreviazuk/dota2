# P4 AI 与内容 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建完整的三层 AI 架构（团队宏观战略层、个人战术效用打分层、微操协同施法层）、中立精英怪与肉山 BOSS 系统（含不朽之守护）、多难度行为调校与细化结算界面（展示 6 格装备、伤害图表与 MVP 评定）。

**Architecture:** 
- `src/sim/entities/elites.ts` & `roshan.ts`: 精英怪（半人马、头狼、萨特、黑龙、岩石傀儡）与肉山 Boss 属性、技能与波次逻辑。
- `src/sim/items/aegis.ts`: 不朽之守护（Aegis of the Immortal）击杀肉山掉落、死亡 5 秒原地满血复活、5 分钟过期化为药膏。
- `src/ai/teamAI.ts`: 宏观战略层（每 1 秒执行），根据双方存活、兵线位置、塔血量与肉山状态，决策团队模式（`laning` / `pushing` / `defending` / `retreating` / `teamfight` / `roshan`）与集火目标。
- `src/ai/utilityAI.ts`: 个人战术 Utility AI 打分框架（每 0.2 秒评估），包含正反补、塔仇恨规避、残血撤退回城、追击与保护。
- `src/ai/microAI.ts`: 技能连招序列（跳吼刃甲、吹风接光击阵等）、走砍与施法预判。
- `src/ai/difficulty.ts`: 难度参数调准（反应延迟、预判误差、补刀成功率、敌方经验金钱倍率）。
- `src/render3d/models/elites.ts`: 精英怪与肉山的 3D/2D 模型与技能特效。
- `src/ui/screens.ts` & `styles.css`: 升级结算界面（6 格神装图标、伤害与承伤图表、MVP 荣誉评定）。

**Tech Stack:** TypeScript 7（strict）、Vite 8、Vitest 5、Three.js r186（3D 渲染）、Canvas 2D、原生 DOM、Capacitor 8。

**Spec:** `docs/superpowers/specs/2026-09-29-dota-lane-design.md`（§8 精英怪、§9 电脑 AI、§10.1-10.2 结算界面、§14 P4）。

## Global Constraints

- `src/sim/**`、`src/ai/**`、`src/game/**` 禁止使用 `document`、`window`、`HTMLElement`、`localStorage`、`performance`，禁止 `Math.random()`（`tests/purity.test.ts` 强制校验）。所有模拟随机数来自 `world.rng`。
- 逻辑步长：`TICK_RATE = 30`，`DT = 1/30`。
- 数值以 Dota 2 7.41f 资料（`docs/research/dota2-reference.md` §4）为准。
- 界面文字全部用中文；代码标识符、文件名、技能 id 用英文。
- 每个任务结束时 `npm test`、`npm run typecheck`、`npm run build` 必须全部通过。
- 每个任务的代码变更单独提交，文档进度单独提交 `docs: progress (P4 task N)`。

### Task 3: 三层 AI 架构——团队宏观战略层 (Team Strategy)

- [ ] **3.1 团队态势感知与战略决策**：创建 `src/ai/teamAI.ts`：
  - 每 1.0 秒周期运行一次，天辉和夜魇各自维护战略评估；
  - 指标评估：己方/敌方存活人数、双方建筑血量优势比、前沿兵线推进坐标、肉山刷新状态；
  - 战略模式切换：
    - `laning`：对线期（前 3 分钟或兵线均衡时）；
    - `pushing`：推线压制（敌方减员或己方兵线优势）；
    - `defending`：塔下防守（兵线压近己方防御塔或己方减员）；
    - `retreating`：溃退重整（团战失利、全队残血）；
    - `teamfight`：正面交战（双方在战线接触且势均力敌）；
    - `roshan`：肉山突袭（敌方关键英雄阵亡且肉山存活）。
- [ ] **3.2 团队战术目标与集火协同**：
  - 战略层输出队伍建议集结线 `rallyPoint` 与集火核心目标 `priorityTarget`；
  - 队友之间共享集火目标，避免伤害分散。
- [ ] **3.3 单元测试**：编写 `tests/ai/teamAi.test.ts`，验证不同局势下战略模式的正确转换与集火目标设定。

### Task 4: 三层 AI 架构——个人战术打分层 (Utility AI) 与对线正反补

- [ ] **4.1 候选行为 Utility 评估框架**：创建 `src/ai/utilityAI.ts`：
  - 每 0.2 秒对 8 类候选行为计算动态评分（0–100 分）：
    1. `last_hit`：正补（斩杀线计算，考虑普攻前摇与弹道时间）；
    2. `deny`：反补（友方小兵血量 < 50% 时反补压制敌方经验）；
    3. `harass`：安全消耗敌方英雄；
    4. `push_tower`：配合小兵进攻防御塔；
    5. `avoid_tower`：敌方防御塔仇恨警觉与脱离；
    6. `retreat_safe`：残血安全撤离或塔后回城；
    7. `use_consumables`：安全脱战状态下吃树/大药/魔棒急救；
    8. `chase_kill`：追杀残血脱节敌人。
- [ ] **4.2 防御塔仇恨规避机制**：
  - 敌方防御塔射程内禁止普攻敌方英雄（防止吸引塔仇恨），除非目标必定被 1 次攻击或技能斩杀且自身血量安全。
- [ ] **4.3 单元测试**：编写 `tests/ai/utilityAi.test.ts`，验证正反补打分优先级、塔仇恨规避行为与残血回城决策。
