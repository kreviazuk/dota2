# P3 物品与商店 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现完整的物品与商店系统。包括 7.41f 的全部核心物品数据（消耗品、属性件、基础配件、鞋子、前中期装备、防御大件、武器大件、功能大件，约 40+ 件物品及合成配方）；6 格物品栏、自动合成、原价退款与半价出售；物品被动属性与攻击特效（连环闪电、重击、暴击、减甲、分裂、吸血、格挡、光环等）；物品主动技能与 `useItem` 指令（BKB、跳刀、刃甲、推推、风杖、相位、魔杖、吃树/大药等）；10 名英雄的阿哈利姆神杖与魔晶强化及新技能（放入 X2 槽位）；代码程序化绘制物品图标；原生 DOM 商店界面、HUD 6 格物品栏与快捷购买组件；10 名英雄推荐出装与 AI 自动出装/施法；批量模拟验证物品对局节奏与平衡。

**Architecture:** 
- `src/sim/items/`：纯逻辑物品模块。数据定义（`definitions.ts`）、合成树与买卖（`inventory.ts`）、被动与攻击特效（`passives.ts`）、主动效果（`actives.ts`）。
- `src/sim/heroes/`：10 名英雄接入 A 杖（Scepter）与魔晶（Shard）效果判定。若赋予新技能，槽位统一使用 `X2`（幻刺 X1 为魅影无形）。
- `src/sim/stats.ts` 与 `systems/attack.ts` / `damage.ts`：将物品属性、攻击特效、伤害格挡、法术阻挡等统一接入属性计算与战斗管线。
- `src/render/` 与 `src/ui/`：程序化图标绘制（`itemIcons.ts`，基于 Canvas 2D，分类底色 + 矢量图形/汉字缩写）；HUD 物品栏与快捷购买按钮（`hud.ts`）；商店弹窗界面（`shop.ts`）。
- `src/ai/`：10 名英雄推荐出装清单（`builds.ts`）；AI 经济思考周期自动购买散件；AI 主动物品施放规则（`itemUsage.ts`）。

**Tech Stack:** TypeScript 7（strict）、Vite 8、Vitest 5、Three.js r186（3D 渲染）、Canvas 2D（程序化图标与 2D 后备）、原生 DOM（界面）、Capacitor 8。

**Spec:** `docs/superpowers/specs/2026-09-29-dota-lane-design.md`（§6.4 神杖与魔晶、§7 物品与商店、§10.2 HUD、§14 P3）。数值与机制参考：`docs/research/dota2-reference.md` §2（物品全表）、`docs/research/dota2-heroes.md`（10 名英雄神杖与魔晶机制）。

## Global Constraints

- `src/sim/**`、`src/ai/**`、`src/game/**` 禁止使用 `document`、`window`、`HTMLElement`、`localStorage`、`performance`，禁止 `Math.random()`（`tests/purity.test.ts` 强制校验）。所有模拟随机数都来自 `world.rng`。
- 逻辑步长：`TICK_RATE = 30`，`DT = 1/30`。
- 数值一律以 Dota 2 7.41f 资料（`dota2-reference.md` 与 `dota2-heroes.md`）为准。
- 界面文字全部用中文；代码标识符、文件名、物品 id 用英文（例如 `black_king_bar`、`blink_dagger`、`power_treads`）。
- 每个任务结束时 `npm test`、`npm run typecheck`、`npm run build` 都必须全部通过。
- 每个任务的代码变更单独提交，文档进度单独提交 `docs: progress (P3 task N)`。

## Decisions（P3 关键设计决策）

| # | 问题 | 决定 |
|---|---|---|
| D35 | 背包容量与格子 | 6 格背包，不设备用背包（单路快节奏手游简化）。消耗品同类堆叠（树枝不堆叠，树之祭祀按 3 次/组堆叠，大药/净化/芒果/仙灵火可堆叠）。 |
| D36 | 购买地点与信使 | 随时随地购买（无神秘商店限制，无信使），买下后物品直接进入英雄背包。 |
| D37 | 散件自动合成 | 购买成品时，若金钱足够且背包空间允许，自动买齐缺少的散件并立即合成。若背包满但所需散件凑齐刚好能在当前格子合成，允许直接购买合成。 |
| D38 | 出售与退款 | 购买后 10 秒内未造成/受到敌方英雄伤害且未使用过的物品，原价 100% 退款；超过 10 秒按 50% 出售。 |
| D39 | 神杖与魔晶形态 | 阿哈利姆神杖（4200 金）进入物品栏并提供 +10 全属性、+175 生命、+175 魔法；阿哈利姆魔晶（1400 金，15:00 后可买）购买后直接消耗生效（不占物品栏）。英雄带有神杖或魔晶时自动激活对应的技能与强化。 |
| D40 | 新技能槽位分配 | 10 名英雄由神杖或魔晶获得的新主动技能统一配置在 `X2` 技能槽（幻刺的 X1 为先天魅影无形，其他英雄 X1 空闲，保持 X2 为神杖/魔晶专用键，统一交互逻辑）。 |
| D41 | 物品主动技能操作 | 物品主动技能共用技能施法框架（轻点智能施法、按住拖动瞄准、拖到取消区取消）。跳刀受到敌方英雄伤害后进入 3 秒冷却禁用。 |
| D42 | 物品图标生成 | 不引用外部图片素材，通过离屏 Canvas 2D 动态生成 64x64 图标纹理：背景按物品分类采用深红/蓝/绿/金等渐变底色，前景绘制矢量几何图形或 1–2 个字简写。 |

### Task 2: 6格物品栏系统、经济买卖、10秒退款与自动合成

- [x] **2.1 背包数据结构与英雄挂载**：在 `Unit` / `Hero` 上挂载 `inventory: (ItemInstance | null)[]`（长度 6，初始为空）。
- [x] **2.2 自动合成算法**：创建 `src/sim/items/inventory.ts`。实现 `checkAndCombine(unit)` 递归检测算法：当背包内拥有某成品的所有组件（含卷轴购买）时，消耗组件，并在原位置生成成品物品。
- [x] **2.3 购买逻辑与自动补齐**：实现 `buyItem(world, unit, itemId)`。
  - 若金钱充足且背包有空位，直接购入；
  - 若为成品且当前散件不足：递归计算所需全部未拥有组件的总价格，若总金钱足够且购买过程中的空间满足合成条件，一次性扣除金钱并自动合成。
  - 记录购买时间戳 `buyTime` 与 `costPaid`，用于退款判定。
- [x] **2.4 出售与 10 秒原价退款**：实现 `sellItem(world, unit, slotIndex)`。
  - 若 `currentTime - buyTime <= 10.0` 且未在战斗中使用过，100% 全额退还金钱；
  - 否则返还 50% 金钱。
- [x] **2.5 指令系统与事件**：在 `commands.ts` 中实现 `buy` 与 `sell` 指令接入；广播 `itemBuy`、`itemSell`、`itemCombine` 事件。
- [x] **2.6 属性更新集成**：修改 `src/sim/stats.ts` 中的 `calculateStats`，遍历存活英雄背包中的所有物品，累加所有被动属性（全属性、三维、攻击力、攻速、移速、护甲、魔抗、生命恢复、魔法恢复、攻击距离等）。
- [x] **2.7 单元测试**：编写 `tests/items/inventory.test.ts`，测试背包满格、自动补齐配件合成、10秒退款与超时半价折损、属性实时生效。
